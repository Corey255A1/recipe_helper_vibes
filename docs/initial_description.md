# Introduction
A Node JS/express based weekly AI (gemini powered) meal planning application. A user should be able to enter and save a "rule" or "context" for the types of meals that they are looking for in plain descriptive language. The server should have a markdown file cache of recipes that the AI/server can build up over time of recipes the user has enjoyed. A history of the weekly meal selections should be stored to ensure a non repetative rotation of meals. When the user requests, the AI/server should do two things, look at the history, choose some meals from cache, and search the web for new recipes to recommend. It should present 10 meal options to the user that the user can choose from three options, never, not this time, yes. The recipe card should show the ingredients, steps, and estimated time for prep and cook and how many people it feeds or servings it makes. Choosing not this time or yes, the server/AI should convert to markdown and store in the recipe cache. Choosing Yes queues it for the current week. Based on the users initial rule or context, they might want some recipes that make enough for multiple days, so consider this when defining the UX of the app. Once the selections for the week are complete, the AI should analyze the selected recipes and present the user with a grocery check list that combines common ingredients and that can be easily copied.
